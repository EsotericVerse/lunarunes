# LRS Scene Blueprint — 設計圖即規格

只處理 LunaRunes 遊戲體驗。以既有符文原畫和 LRS 已實作玩法為基礎，不照搬 LOC 網站管理、SaaS、授權或 SQL 流程。

## 場景設計需要時使用的規格
- **場景圖**：玩家看見什麼，符文／牌陣／遊戲盤的位置、景深、資訊層級、桌面及手機畫面差異。
- **行為圖**：進場 → 可選操作 → 動作反饋 → 狀態變更 → 結果 → 返回／再玩。對不可操作、讀取中、失敗及取消給出可見反饋。
- **動態分鏡**：手勢觸發點、翻牌與鏡頭節拍、3D 特效起止、可跳過與降低動態。
- **玩法契約**：區分符文占讀、圖鑑、桌遊和模擬人生的玩法；既定抽牌、方向、月相和回合規則不得為畫面效果而改寫。
- **驗收圖**：至少明列初始、操作中、結果、異常四種狀態，以及手機觸控、桌機鍵盤與返回行為。

## 行為優先，工程居後
新場景或大型互動修改可先用可審視的設計圖（版面草圖、流程圖或分鏡規格）說明體驗，再選用既有實作；局部微調直接比較實際畫面與操作即可。必要時才修改引擎。不得用通過 build、增加套件或 API 數量取代場景完成。

## 交付判定
交付能用本次採用的設計依據、畫面比較或操作規格驗收的實際場景，註明已實測與未實測狀態。局部配色／材質修正直接對照畫面即可；大型互動場景才以完整設計圖對照。按需要組合 art-direction、game-feel、3D／特效等 Skills，不把它們當固定先後順序。
