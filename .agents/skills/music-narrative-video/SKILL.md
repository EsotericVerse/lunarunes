# 音樂敘事轉影像（LRS）

這是 LRS 的音樂敘事入口，負責把歌曲的情緒、歌詞、段落與時間軸轉成視覺故事、分鏡及可剪輯影片規格。它是創作協調技能，不是影片生成器，也不取代 LRS Framework。

## 何時使用

- 使用者要求歌曲轉 MV、歌詞轉影像、音樂愛情故事、動畫 MV、敘事型歌詞影片或音樂短片。
- 使用者已有歌曲或歌詞，希望將它發展成有角色、場景與情節的視覺作品。
- 使用者要求把既有故事與歌曲結合，並以歌曲時間軸作為影片結構。

純歌詞創作、歌曲編曲討論、一般音樂問答、LRS 遊戲內音效或符文抽牌特效，不觸發本技能。

## 創作主權與來源規則

1. 使用者提供的歌曲、歌詞、故事、角色與意象是第一手來源。不得擅自改寫歌詞、增刪句子、調整段落順序或把歌詞改成角色對白。
2. 歌詞是視覺敘事的情緒與語意錨點，不代表每一句都必須逐字具象化。可用人物行動、場景轉換、象徵物、光線與鏡頭表現其意義，但不得扭曲原意。
3. 不替歌曲虛構 BPM、拍點、精確時間碼或音樂段落。取得音檔並能實際分析時才標記精確數據；沒有音檔或測量工具時，將段落與時間標為暫估。
4. 不把每首歌強制改成短劇分集。依作品選擇歌詞影片、敘事 MV、音樂愛情故事或動畫 MV。
5. 原創歌曲與角色的既定風格不受 zh-tw-writing 的一般說明文體限制；使用者可見的企劃與交付說明則遵循台灣繁體中文。
6. 一般小說／愛情故事不套用遊戲專用的 narrative-design；只有使用者明確指定符文世界時，才依 LRS Canon 使用該技能。不得為了視覺效果改動符文名稱、語意或規則。

## 工作流程

### 1. 確認作品形態與素材

先辨識本次目標：
- 歌詞影片：以歌詞顯示、段落節奏、字體動態與可讀性為主。
- 敘事 MV：以人物、事件、情緒弧線與視覺隱喻為主。
- 音樂愛情故事：建立關係變化與完整情感敘事，但不必套用短劇集數。
- 動畫 MV：先確立視覺風格、角色造型與動作語言，再設計鏡頭。

讀取使用者已提供的歌曲音檔、歌詞、故事或視覺參考。若缺少會直接影響製作的必要素材，只問一個最關鍵的問題；其他細節採合理預設並標示。

### 2. 建立歌曲時間軸

將歌曲拆成實際存在的段落，例如 Intro、Verse、Pre-Chorus、Chorus、Bridge、Instrumental、Outro；不假設每首歌都有全部段落。

每段記錄：
- 起訖時間；有實際音檔分析結果時使用精確時間，否則標示暫估。
- 歌詞範圍或無人聲段落。
- 情緒、能量、節奏密度與音樂變化。
- 該段在整體故事中的敘事功能。

副歌重複時，先判斷是否需要重複同一畫面、改變畫面意義或呈現人物／關係的新狀態，不機械複製鏡頭。

### 3. 建立視覺故事

整理一份短而清楚的視覺企劃：
- 一句話故事核心。
- 主要人物與關係。
- 時間、地點與主要視覺意象。
- 從開場到結尾的情緒變化。
- 歌曲高潮對應的視覺高潮。
- 結尾如何回應歌曲主題。

讓故事隨音樂推進；避免把歌詞逐句翻譯成畫面，也避免為了湊滿時長加入無意義場景。

### 4. 轉成視覺製作文件

依需要建立以下交付物，不要求每個作品全部建立：
- 音樂企劃.md
- 歌曲時間軸.md
- 視覺故事.md
- 視覺設定.md
- 分鏡.md
- 影片提示詞.md
- 剪輯單.md

可按需組合 Drama Skills：
- 原著或故事拆解：short-drama-novel-analyze、short-drama-develop。
- 劇本化的敘事 MV：short-drama-write；只有確實需要場景劇本時才使用。
- 角色、場景與道具：short-drama-assets。
- 靜態視覺提示詞：short-drama-image-prompts。
- 鏡頭設計：short-drama-storyboard。
- 動態、運鏡、口型與聲音提示詞：short-drama-video-prompts。
- 跨文件與成片檢查：short-drama-review。

沒有完整短劇專案目錄時，優先使用相關 Skills 的輕量模式，不強制建立 EP、SHOT、MOTION 等完整機讀欄位。只有在需要正式專案校驗或批量投產時，才採用 Drama Skills 的標準專案格式與檔名；為相容其工具，必要的機讀欄位與固定檔名保留原規格，文件正文仍使用台灣繁體中文。

### 5. 進入影片製作

素材與提示詞定稿後，才按需啟用既有 hyperframes 技能，將歌曲、影片片段、字幕、字卡與動態畫面組合成可剪輯專案或成片。

HyperFrames 是影片合成／呈現層；Drama Skills 負責故事、分鏡與生成提示詞。不要把影片專案依賴加入 LRS Framework、Web runtime 或 IPA 建置。

### 6. 生成與費用界線

- 寫企劃、劇本、分鏡與提示詞不等於授權生成媒體。
- 不自動呼叫外部圖片、影片、配音或配樂 API。
- 使用 short-drama-produce 時，必須先依其規範列出本批任務、模型、參數、輸出路徑與費用影響，讓使用者看到完整預覽後，再取得本次明確確認。
- 不在 Repo、Markdown、範例或輸出紀錄中保存 API Key、Secret 或私有供應商憑證。
- 不擅自上傳使用者的歌曲、歌詞、人物照片或其他素材至外部服務。

## 預設交付

先交付一份可審視的歌曲時間軸與視覺故事，再依使用者要求擴展成角色設定、分鏡、影片提示詞及 HyperFrames 專案。使用者要求直接完成全套時，可連續完成各階段，但不可跳過素材來源核對或付費生成確認。
